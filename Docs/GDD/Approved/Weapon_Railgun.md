# Weapon: Railgun — Рельсотрон

**Статус:** Approved  
**Тип:** Hitscan + penetration  
**Связано:** [[Damage_System]], [[Tank_Aim]], [[Match_Framework]]

## Фэнтези

Снайперское hitscan-орудие: накопление заряда, мощный луч, сквозное пробитие нескольких целей, стены останавливают луч.

## FSM

```
        setFire (level) + alive + fireTimer ≤ 0
IDLE ──────────────────────────► CHARGING
  ▲                                 │
  │                    release (player) → NO-OP (M20)
  │                                 │
  │                          chargeTimer ≥ chargeTime
  │                                 ▼
  │                          executeFiring() (synchronous)
  │                                 │
  └───────── COOLDOWN ◄─────────────┘
              reloadTimer → 0
```

- Старт заряда: **level-trigger** (`railgunShouldStartCharge`) — ИИ может держать fire и перезаряжать.
  Гейт `fireTimer ≤ 0` уважает базовый контракт `Tank.canFire`.
- **Неотменяемый выстрел (M20; заменил cancel-on-release M18):** игрок, отпустив fire во время
  CHARGING, НЕ сбрасывает заряд — `railgunShouldCancelCharge` удалён, отпущенный триггер это no-op.
  Начатый заряд всегда доходит до выстрела. Это убирает наказание за «отпустил раньше 1.1 с» и
  делает спуск «просто кликом». Единственный выход из CHARGING до выстрела — смерть владельца
  (`onOwnerDeath`). Боты и раньше не отменяли (их `wantsFire` мигает покадрово).
- `chargeTime` / `reloadTime` делятся на `ownerReloadMul` (бафф reload).
- Переход CHARGING→выстрел выполняется синхронно в том же кадре, когда заряд достиг порога
  (отдельный transient-state FIRING удалён из типа `RailgunState`: был недостижим,
  а его safety-ветка делала «призрачный» выстрел с пустыми списками целей).

### Смерть владельца

При переходе `alive → !alive` оружие получает `onOwnerDeath()`:
- state сбрасывается в IDLE; таймеры обнуляются;
- charge-audio останавливается (если этот экземпляр его запустил);
- луч мгновенно скрывается (`beamFx.hide()`), свет отцепляется;
- FOV tighten очищается для игрока;
- `barrelGroup.position` жёстко сбрасывается в rest и `setBarrelKick(0)` —
  `restoreDeathVisuals` при респауне сбрасывает только rotation, без этого танк
  умирал со смещённым зарядным jitter-стволом и жил с ним до респауна.
- свечение `rail`-слота (`railGlowMat.emissiveIntensity`) обнуляется:
  glow-материал не входит в `bodyMats`, которые обнуляет `animateDeath`, а
  мёртвый владелец больше не обновляет оружие (`WeaponSystem` пропускает
  `!alive`) — без сброса труп лежал до респауна со светящейся «заряженной»
  рельсой.

Это предотвращает «призрачный» выстрел после респавна и зависание визуалов mid-fade.

## Логика пробития (`executeFiring`)

1. Raycast far = `range` (`Infinity` → игровой фолбэк `RAY_RANGE_FALLBACK = 1000` в `RailgunWeapon`: вся арена 300×300 накрыта с запасом; поиск блокеров `nearestShotBlockerDist` маппит не-конечный range в свой физический safeRange `10000`) по мешам танков + арене.
2. Сортировка попаданий по дистанции.
3. Для каждой цели-танка:

```
dmg   = round(currentDamage)
force = knockback * (currentDamage / baseDamage)
applyHit(...)
currentDamage *= 0.65
```

4. Стена / destructible block **останавливает** луч (M18: `beamFx.setLength(wall.dist)` укорачивает единый mesh дуги; раньше двигался только impact-light и луч визуально проходил сквозь стену). Блоку — `damageBlock` с текущим `currentDamage`, но только если `round(currentDamage) > 0` (после N пробитий остаток может округлиться в 0 — FX показывается, урон нет).
5. `nearestShotBlockerDist` учитывает гео-блокеры; порог высоты вынесен в константу `SHOT_HEIGHT_EPS` (единая со снарядом пушки, `src/game/engine/physics.ts`). Коллайдер, в footprint которого попало само дуло (танк вжался в стену/угол), блокером **не** считается: вход в slab остался за началом луча, а `segmentHitT` для origin внутри AABB всегда отвечает `0` — без скипа выстрел умирал в нулевой дистанции и пилил собственный блок.
6. HUD-прицел ставится на **термин** луча (стена/дальность), а не на первого
   танка на линии: цели луч не останавливает — `pierceTanks` в
   `reticleImpactDistance` (см. [[Player_Controls]] §«Логика прицела»).

Урон: `resolveWeaponDamage(params.damage, tuning.damage)` — боты матча: `BOT_NORMAL.damageScale`.

## Shot feel (M19 + Feel Overhaul)

1. **Pitch ramp и Pre-fire gap:** во время CHARGING оружие каждый кадр вызывает
   `audio.setChargeRailgunPitch(progress)` — базовые слои charge-гула поднимаются
   по progress² до +35% частоты на полном заряде. За ~0.07 с до выстрела нарастающий
   звук резко затихает в вакуумную точку (`pre-fire anticipation gap`), создавая
   драматический акустический контраст перед залпом.
2. **Tracer delay:** урон/knockback/пинги пробития разрешаются мгновенно,
   но луч + impact-FX + ионный трейл собираются в `PendingShotVisual` и
   воспроизводятся через `tracerDelay` (0.025 с) после выстрела:
   muzzle-flash → борт-хлопок → луч. Смерть/`dispose` в окне задержки
   отменяют pending-визуалы (призрачного луча от мёртвого танка нет).
2b. **Бегущий фронт луча (M20):** вместо мгновенной вспышки всей длины `show()`
   рисует короткий stub у дула, а `BeamSweep` ведёт фронт к термину со скоростью
   `beamFrontSpeed` (2400 юнитов/с). Каждое событие (penetration-импакт, ионная
   puff’а, wall-терминус) срабатывает, когда фронт **проходит** его `d` от дула:
   выстрел визуально «прошивает» линию. Ближний бой (d заходит за 1 кадр) —
   импакт почти мгновенный; дальний снайп — видимый пробег. `PendingShotVisual`
   хранит `d` для каждого pierce (`hit.distance`) и wall (`wall.dist`).
   Смерть/`dispose` обнуляют активный `beamSweep` (его события не стреляют за
   мёртвый танк).
2c. **Плотный ионизационный след (Ion Trail):** таймлайн свипа несёт
   `segs = clamp(⌊длина/12⌋, 3…10)` puff’ов `trailPuff` (светящиеся медленно
   всплывающие искры + мягкий ионизированный дым, тающий за ~0.65 с). Средний
   из них дополнительно бьёт `railgunImpact` в воздух как ионизационная сердцевина.
2d. **Muzzle Shockwave Ring & Cooling Steam:** срез ствола в момент выстрела
   рождает расширяющуюся кольцевую ударную волну (`ring` 2.8), а в первые 1.2 с
   кулдауна раскалённые рельсы стравливают лёгкий пар охлаждения (`spawnSmoke`).
3. **Кинематографичный звук выстрела:**
   - Layer 1: Sub-bass boom (56→20 Гц) — плотный низкочастотный удар.
   - Layer 2: Mechanical slug punch (180→28 Гц square) — массивный толчок затвора.
   - Layer 3: Supersonic crack (4.5 кГц highpass noise + 2.6 кГц sweep) — резкий хлыст разрыва воздуха.
   - Layer 4: Plasma sizzle tail — затухающее шипение плазмы на 0.32 с.
4. **Penetration feedback (Armor Crunch):** каждому пробитию — свой цвет impact из
   `pierceColors` (1-й ярче, 3-й+ тусклее) + сокрушительный металлический хруст
   пробития брони `audio.railgunPierce(index)` (punch square + triangle + bandpass/highpass crunch)
   вместо плоского бипера. Wall-терминус остаётся оранжевым (`0xffa040`) + debris.
5. **Динамический прицел (Reticle Charge):** во время зарядки засечки перекрестия
   плавно стягиваются к центру (`--charge-prog`), центральная точка разгорается
   ярким cyan-свечением, при 96%+ срабатывает импульс готовности (`.is-charged`),
   а в кадр выстрела прицел масштабно разлетается (`.shot-pulse`).
6. **Тряска от bot-выстрела — по радиусу:** `fireShakeBot` доходит до камеры
   только когда живой игрок в `fireShakeBotRange` (45, XZ) от стреляющего бота.

## Contact charge balls (M21)

Перед выстрелом на дуле «сходятся» два шара — читаемый индикатор накопления
заряда, синхронный с glow/FOV/pull (все едут от одного `progress`):

- **Электрический шар** (аддитивный, цвет 0x8fffe8) нарастает `electricStart →
  contactRadius` по **p²** — «накапливается», выпукло; на полном заряде «кипит»
  (пульс масштаба ±8%).
- **Белый «воздушный» шар** (обычный блендинг, под glow) схлопывается
  `airStart → contactRadius` вогнуто — `1−(1−p)²`: сначала быстро, к концу
  замедляется; opacity растёт по мере сжатия, но остаётся полупрозрачной
  (`0.08 → 0.30`), а электрический стартует с opacity 0.55 (растёт до 1.0) —
  иначе аддитивный cyan не пробивается сквозь белый шар и заряд «невидим».
- **Соприкосновение = кадр выстрела.** При p=1 оба радиуса равны
  `contactRadius`. Это совпадает с синхронным firing FSM, отдельно связывать
  ничего не нужно (неотменённый заряд M20 всегда доходит до p=1). В кадр fire
  `confirmFire()` проигрывает короткий pop (0.09 с): электрический втягивается
  в ноль со вспышкой, воздух «хлопает» до `airPopRadius` и гаснет.
- Луч вырастает из точки контакта: стартовый `BEAM_SWEEP_START_LEN` =
  `2·contactRadius` (M21), дальше его ведёт `BeamSweep` (M20).
- Позиция живая — оба шара каждый кадр берут `fillMuzzleAndAim`, поэтому сидят
  на дуле и трясутся вместе с barrel-jitter бесплатно. Показываются и игроку,
  и ботам (заодно PvP-индикатор: видно, что вражеская рельса почти зарядила).
- Единственный досрочный выход — `hide()` при смерти/`dispose` (разрядной
  анимации нет, т.к. выстрел неотменим). Геометрия сферы — module-level
  ref-count (как лента `RailgunBeamFx`).

Радиусы — чистая функция `chargeBallRadii(progress, cfg)` (unit-test без Three);
presentation-класс `RailgunChargeBalls` владеет только mesh'ами/материалами.

## Луч: единая электрическая дуга (M22)

M21 держал три слоя (core / body / glow с эффективными радиусами ≈ 0.08/0.20/0.40)
— «обводка» луча жила именно там: ореол и тело поверх ядра давали толстую каёмку.
В M22 слоёв нет совсем: `src/game/weapons/RailgunBeamFx.ts` владеет **одним**
mesh'ем (лента из двух колонок) и `ShaderMaterial` (additive, `depthWrite: false`,
`premultipliedAlpha: true`, `fog: false`, `side: DoubleSide`). Лента даёт шейдеру
ось луча и поперечный координат `vWide ∈ [−1, 1]`, а **фактическую толщину
назначает шейдер — уже в экранном пространстве**: после проекции вершина уводится
перпендикулярно спроецированной оси на нужное число CSS-пикселей. Все числа в `BEAM_ARC`:

| Что | Как |
|-----|-----|
| Излом дуги | 1D value-noise от **мировой** дистанции вдоль луча: `x = t · uCells`, `uCells = длина / cellLength`, `cellLength = 1.8` юнита; смещение по двум перпендикулярам оси, амплитуда `amplitude = 0.3` юнита |
| Стабильность при бегущем фронте | аргумент шума — дистанция, а не доля длины ⇒ `setLength` не переиначивает уже нарисованную часть: дуга дорастает из дула, не меняя форму |
| Статичный след разряда | `snapSeed = floor(uSeed) * 11.31` (сид фиксируется на выстрел, `snapRate = 0`), форма дуги и нити жгута статичны в пространстве (подобно спирали), не ползут и не дёргаются во времени |
| Ширина = пиксельный пол | `rPx = max(pixelWidth/2 · rs, basePx) · lump`, `basePx = radius · rs · lump / (depth · uPxScale)` — мировая база в пикселях, `rs` — радиальный масштаб меша (он же punch). Вершина уходит на `vWide · rPx` **в пиксельных координатах** перпендикулярно спроецированной оси: `clip.xy += perp · vWide · rPx · uPxToNdc · clip.w`; `perp` — нормализованная в пикселях производная перспективы вдоль оси (при взгляде точно вдоль луча она вырождена — берётся любой перпендикуляр, сечение и так пятно). `pixelWidth = 12` — CSS-пиксели, единственная ручка «толще/тоньше»: яркость ядра упирается в плато ACES, поэтому читаемость добирается площадью, а не числом. `uPxScale = 2 / (H · projY)` — мировых единиц на пиксель на глубине 1 — считает `cssPxScale()` из высоты окна и номинального fov 58° (FOV-панч ±5.5° меняет ширину на ~3 %, платить за него живым состоянием камеры нечем), значение зажато в `[1e-4, 1e-2]`; `uPxToNdc = (2/W, 2/H)` — из `cssPxToNdc()`, размеры окна зажаты по той же причине. Оба обновляются в `show()`. К `renderer`/камере в момент рендера эффект не обращается вовсе: ortho-проход или resize с нулевой высотой иначе обнуляют или раздувают габарит — «луча нет» без единой ошибки. H, W — CSS-пиксели, а не размер буфера: при `pixelRatio` 1 (low) и 2 (high) линия физически одинаковая, просто на high на неё больше сэмплов |
| Перспективная база | `radius = 0.06` юнита выигрывает у пиксельного пола ближе ≈ 6.5 юнитов ⇒ у дула луч жирнеет по-настоящему, а на дистанции держит ровно 12 px вместо прежних «вот ниточка, вот пропала» (без пола 2-пиксельная линия на 120 юнитах сжималась в доли пикселя) |
| Неровность толщины | `lump = 1 ± thicknessNoise (0.3)` по тому же шуму дуги: звенья то раздувает, то ссыхает — ровная трубка читается пластиком |
| Ядро линии | `core = pow(max(0, 1 − abs(vWide)), coreExp = 2)`: горячая нить в середине, мягкие плечи к кромкам, `discard` при `core ≤ 0.002`. Профиль берётся из **экранной** поперечной координаты, а не из `vFacing` трубки: в аксиальном ракурсе косинус нормали уходил бы от центра линии к её краю, и ядро ездило бы поперёк |
| Нити жгута | `strands = 1 ∓ strandAmount (0.26) · pow(0.5 + 0.5·cos(vWide · π · filaments + vPhase), 1.5)`, `filaments = 4`, `vPhase = x · 2.1` (статичные жилы вдоль луча). Это то, что позволяет линии быть толстой и оставаться разрядом, а не залитой полосой — второго слоя ради «массы» не добавляется |
| Пульс и свечение | `vSpark` 0.68–1 (по звеньям, зафиксирован на выстрел) × `vFlicker` 1.0 (ровное свечение без строба) × `head` (×1.5 на терминусе — туда приходит `BeamSweep`); `gain = 1.5` держит ядро выше ACES-плеча и порога bloom 0.85, но НЕ в 255: с ростом ширины вклад аддитивного слоя (яркость × площадь) сам по себе вырос, и прежние 2.0 заливали ядро в сплошную белую профилённую кишку, которую bloom размазывал в ~28 px без внутренней структуры |
| Punch выстрела | `PUNCH_DUR = 0.055 с`: `rs` и амплитуда излома стартуют с `punchScale = 1.9` и стягиваются к 1 / `amplitude` — «разброс → натянутый провод». Множитель доходит и до пиксельного пола (он перемножает `rPx`): кадр выстрела — трещина ~23 px, затем 12 px |
| У дула | первые `muzzleStraight = 1.2` юнита дуга прямая (`smoothstep`), иначе линия «отлипала» бы от ствола |
| Fade | один `uOpacity = t^fadeExp`, `fadeExp = 0.45`, `t` — остаток жизни за `beamDuration = 0.84 с`. Линейное затухание съедало половину яркости к середине жизни, и на светлом фоне дневной карты трассер становился «еле виден» именно там, где его ещё видно; с кривой на половине жизни остаётся ~73 % яркости, а гаснет так же в ноль и тоже целиком — отдельных кривых «тела» и «ореола» нет |

### Плазменная спираль вокруг луча (Variant A — винтовой статичный след)

Вокруг центрального электрического разряда по всей длине формируется винтовая плазменная линия (соленоидный вихрь Лоренца), визуально дополняющая силуэт выстрела:
- **Единый draw call (Zero Draw-Call Overhead):** геометрия спирали не создаёт отдельный `THREE.Mesh`, а упакована во второй саб-стрип того же `BufferGeometry` (лента с `position.y = 1`, 772 вершины и 2304 индекса на оба стрипа суммарно). Шейдер `VERTEX_SHADER` ветвит смещение по флагу `isSpiral = position.y`.
- **Статичный след в пространстве:** угол витка завязан строго на мировую дистанцию вдоль оси выстрела: $\text{angle} = \text{worldDist} \cdot \frac{2\pi}{\text{pitch}}$ (`spiralPitch = 5.2` м). Линия не крутится во времени («статичный след плазмы»), поэтому при разворачивании луча бегущим фронтом `BeamSweep` витки спирали бесшовно дорисовываются вперёд, не проворачиваясь и не дёргаясь.
- **Защита обзора (Muzzle Safe Zone):** первые `spiralMuzzleSafe = 3.0` м радиус спирали плавно нарастает от нуля через `smoothstep(0.0, uSpiralSafe, worldDist)`, исключая перекрытие перекрестия и прицельной зоны перед камерой в виде от 3-го лица.
- **Масштаб и толщина:** базовая ширина линии на экране — `spiralPixelWidth = 4.5` CSS px (против 12 px у ядра). При выстреле punch-масштаб `punchScale = 1.9` раздувает как радиус витка (`spiralRadius = 0.85` м, создавая чистый зазор ~0.55–0.85 м до центральной молнии), так и толщину нити, после чего они мгновенно стягиваются в плотный соленоидный шнур.
- **Цвет и светимость:** цвет `0x8fffe8` (cyan палитры рельсотрона), мягкий спад профиля `pow(1 - |vWide|, 1.4)`, множитель `spiralGain = 1.4` и аддитивное затухание синхронно с общим `uOpacity`.

Замер по пикселям (1280×720, порог светимости 190 на фоне земли 127–130).
Превью, луч через экран: устоявшаяся дуга — симметричный профиль с горячим ядром
**13 px** (≥190 от −3 до +9 px от центра), плато 245–255 sRGB, суб-нити читаются
внутри линии; кадр punch — прогоны p50/p90/max = 7/16/38 и 2.21 % светлых пикселей
кадра; на `q=medium` (без bloom) те же 13 px и 5/11/24 — виден и без послесвечения.
Живой матч (`q=low`, луч почти аксиален, ON/OFF/ON-дифф одного замороженного
кадра): дуга добавляет **5.36 % пикселей кадра** (вместе с двумя огнями луча)
против 0.37 % до перехода на экранную толщину — это ровно тот случай, который
боковое превью не ловило. «Видно» собирается площадью и ракурсом, а не яркостью:
выше ~250 sRGB ACES не пускает.

Часы шейдера (`uTime`) локальные и идут, только пока луч жив: `update(dt)` при
нулевых таймерах выходит сразу. `show()` перед каждым выстрелом возвращает mesh в
сцену, если тот остался без родителя (пересборка арены / teardown между выстрелами
иначе ронял луч в «эффекта нет» без единого сообщения об ошибке). Цвет ядра белый
(`coreColor`), кромка —
общий cyan палитры (`edgeColor = 0x8fffe8`, как `pierceColors[0]` и шары заряда).
Семантика `show / setLength / setImpactPosition / hide / update / dispose`,
muzzle/impact-свет из `LightRig` и весь FSM не изменились — `RailgunWeapon` под
правку не трогался вообще.

### Beam-огни: claim слотов и вспышка импактов (hotfix)

Слоты `beam[0]/beam[1]` — постоянный бюджет `LightRig` на все рельсотроны, но
писать в них разрешено только владельцу: `show()` забирает claim обоих слотов,
`setLength`/`setImpactPosition`/`update` пропускают чужие, `hide()`/`dispose()`
гасят и отпускают только собственные (тот же арбитраж, что `flame`-слот в
`FlameParticlePool`). Без него второй одновременный выстрел переставлял огни
первого, а `hide()` доигравшего луча тушил свет ещё живого.

Каждый импакт бегущего фронта перезаряжает вспышечный envelope `impactPulse`
(затухание за 0.12 с); `update()` пишет `max(fade t, impactPulse) · PEAK`.
Прежний bump в `setImpactPosition` перезаписывался fade-кривой в том же кадре
(`max(текущее, 0.75·PEAK)` при `t ≈ 0.9` никогда не выигрывал), и вспышек
пробитий фактически не было.

## Аммуниция (HUD)

`getAmmoState`: magazine 1; `isCharging` / reload progress из FSM.
`reloading` при этом **true и на CHARGING, и на COOLDOWN** (общее кольцо
прогресса), поэтому потребители разделяют состояния сами: `weaponStatusKind`
(HUD-статус) и `liveRegionKey`/`liveRegionText` (озвучка для screen-reader)
— заряд объявляется как «Зарядка», «Перезарядка» звучит только на cooldown
(тот же паттерн, что `isReloadNotCharge` в `PlayerInputStage`).
